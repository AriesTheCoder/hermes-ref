# Limits and data handling

- Workspace argument strings are bounded: title 200 characters; outline/replacement strings 60000 characters; list offset 0–50000. Runtime validates types and rejects unknown keys.
- Reads use validated pages of 200 lines, at most 100 pages, with a total response-text budget of 262144 characters. Native Ref tools remain available for larger documents.
- Process-local caches hold at most 64 profile/server-scoped session entries, eight turns per session and eight discovery scopes of 32 pages each. Sessions with active operations are not evicted. A finalized session releases its snapshots. Up to 16 distinct failed remote operations are retained per turn; further operations are refused instead of unbounded retry activity. Failed verification clears readiness/snapshots while retaining a recoverable document ID. Non-default MCP server names use separate persisted binding keys.
- Same-session workspace actions are serialised; different sessions can operate concurrently. Discovery fills are serialised and worker calls copy active context. Guidance TTL is one hour; listing TTL is 60 seconds. Session eviction may cause guidance to be emitted again.
- Explicit outlines and edits go to the configured Ref Plans MCP server. The operator's per-server grant may include write-capable tools. Existing document sharing is unchanged; only new creation explicitly requests private visibility.
- The journal at `plugin-data/hermes-ref/workspace.sqlite3` holds hashed session keys, document IDs, creation-attempt status and migration metadata, not document bodies. Snapshots stay in process memory. On first journal use, old `plugin-state/hermes-ref/workspace.sqlite3` rows are imported transactionally and the original is retained unchanged; destination conflicts retain the destination row.
- Registration does no network or journal I/O. First journal use creates the data directory/database. Removing or disabling the plugin does not delete remote documents, retained journal data or the legacy journal.
- Public tool-execution middleware supplies exact call identity. Calls that bypass it must carry explicit host session/turn keywords; missing identity returns an error, never a guessed session or a private-host fallback.
